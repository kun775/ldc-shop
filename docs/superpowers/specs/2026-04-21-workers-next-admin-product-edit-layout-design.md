# `_workers_next` 后台商品编辑页双栏布局与固定侧边栏设计

## 1. 背景

当前 `_workers_next` 后台商品新建/编辑页仍然采用单列长表单，核心问题比较直接：

- 商品内容编辑字段和运营配置字段混在同一条阅读流里，视觉负担重
- 表单很长，保存按钮位置过低，编辑中后段时操作效率差
- 桌面端后台侧边栏不会固定，切换页面和长页面滚动时导航效率一般
- 随着商品能力继续增加，现有单文件单列布局会越来越难维护

用户已明确确认新的目标方向：

- 整个后台桌面端改为固定左侧侧边栏
- 移动端继续使用顶部入口 + 抽屉菜单
- 商品编辑页改成“左侧内容编辑、右侧配置与操作”的双栏布局

本次需求本质上是后台信息架构和编辑体验重组，不是业务规则调整。

## 2. 目标

本次设计目标如下：

- 桌面端后台左侧菜单固定，右侧主内容区独立滚动
- 商品新建页与编辑页统一使用双栏布局
- 左栏承载商品核心内容编辑，右栏承载运营配置与保存操作
- 保存按钮在桌面端始终容易触达，不再依赖滚到表单底部
- 保持现有商品保存逻辑、字段契约和移动端导航方式不变
- 通过合理拆分组件，避免继续把商品表单堆成一个超大文件

## 3. 范围

### 3.1 本次范围内

- `_workers_next` 后台桌面端整体骨架调整
- 商品新建页 `/admin/product/new`
- 商品编辑页 `/admin/product/edit/[id]`
- 商品表单 UI 结构重组
- 商品编辑页子组件拆分

### 3.2 不在本次范围内

- 不修改 `saveProduct()` 的服务端保存逻辑
- 不新增商品业务字段或修改字段含义
- 不重做移动端后台导航结构
- 不对后台所有页面做视觉重设计
- 不引入新的全局状态管理方案

## 4. 现状分析

### 4.1 后台骨架现状

后台布局位于：

- `_workers_next/src/app/admin/layout.tsx`
- `_workers_next/src/components/admin/sidebar.tsx`

当前桌面端结构是：

- 外层 `flex`
- 左侧 `AdminSidebar`
- 右侧 `main`

但侧边栏本身只是普通流式布局，不是固定定位，也没有独立的桌面端滚动策略。因此在长页面中：

- 侧边栏会跟着页面整体一起滚动
- 导航在桌面端的停留性不够

### 4.2 商品编辑页现状

商品表单位于：

- `_workers_next/src/components/admin/product-form.tsx`

当前实现特点：

- 使用单个 `Card` 包裹整个表单
- 表单宽度限制在 `max-w-2xl`
- 所有字段沿单列顺序向下堆叠
- 状态、图片上传、购买提问、积分抵扣等交互全部集中在一个组件内部

这会带来几个直接问题：

- 内容编辑与运营配置没有主次区分
- 大量滚动导致保存动作不够高频可见
- 后续继续加配置项时，单列结构的可读性会持续下降
- `product-form.tsx` 的维护复杂度已经偏高

## 5. 设计原则

本次设计遵循以下原则：

- 优先重组信息结构，不碰业务逻辑
- 左侧承担“创作/编辑”，右侧承担“设置/发布”
- 桌面端优化效率，移动端保持稳妥兼容
- 主内容只保留一个纵向滚动上下文，避免多层嵌套滚动
- 在不改变保存契约的前提下拆分组件，降低文件复杂度

## 6. 后台骨架设计

### 6.1 桌面端固定侧边栏

桌面端后台布局调整为：

- 左侧固定宽度侧边栏，宽度约 `256px`
- 侧边栏固定在视口左侧，高度占满可用视口
- 右侧主内容区自动填满剩余宽度
- 页面滚动只发生在右侧主内容区

这样可以保证：

- 导航始终可见
- 后台长页面的上下文稳定
- 商品编辑页双栏布局更容易成立

### 6.2 移动端保持现状

移动端继续使用当前方案：

- 顶部栏
- 菜单按钮
- 抽屉侧栏

原因很简单：

- 当前模式已经适配移动端空间限制
- 本次重点是桌面端编辑体验，不应把移动端导航一起扩大改造

### 6.3 右侧主内容区滚动策略

桌面端调整后，右侧主区域应承担唯一主滚动容器职责：

- 外层后台页面不再让整体文档流和侧边栏一起滚动
- 商品编辑页内部也不再额外制造整列级二次滚动

目标是避免出现：

- 侧边栏滚一层
- 页面主体滚一层
- 右栏配置卡再滚一层

这种三层滚动对后台编辑场景非常差。

## 7. 商品编辑页布局设计

### 7.1 页面总体结构

商品新建页和编辑页统一使用双栏布局：

- 左栏：商品核心内容编辑区
- 右栏：商品配置与操作区

桌面端推荐栅格：

- 左栏：`minmax(0, 1.7fr)`
- 右栏：固定宽度 `360px`

平板及以下：

- 自动折叠为单列
- 右栏配置区顺序排到左栏内容区下方

### 7.2 页面标题区

编辑页顶部增加页面级标题区，不再只依赖表单卡片标题表达语义。

固定包含：

- 页面标题：`编辑商品` / `新建商品`
- 辅助说明：提示左侧编辑内容、右侧配置发布

这样用户在进入页面时能立即理解页面结构。

## 8. 左栏内容编辑区设计

左栏承载“商品核心内容”，按编辑顺序组织，而不是按数据库字段顺序组织。

### 8.1 区块一：基础信息

包含：

- 商品名称
- Slug
- 商品描述

目标：

- 先完成商品识别信息输入
- 建立页面主要编辑上下文

### 8.2 区块二：价格与购买信息

包含：

- 商品价格
- 划线价
- 每用户限购
- 购买须知

目标：

- 把购买决策相关字段集中在一起
- 避免价格、提示、限制分散到各处

### 8.3 区块三：图片与图库

包含：

- 主图链接或上传
- 主图预览
- 图库输入
- 图库上传
- 图库预览、设为封面、删除

目标：

- 为图片编辑提供足够宽度
- 利用左栏大空间改善图库管理体验

### 8.4 区块四：购买提问

包含：

- 购买提问开关
- 提问列表
- 新增/删除提问

目标：

- 保持提问编辑连续性
- 避免这类动态表单被挤进狭窄配置区

## 9. 右栏配置与操作区设计

右栏承载“运营配置与发布动作”，整体桌面端吸顶。

### 9.1 区块一：操作卡

置于右栏最上方，并设置为主要视觉锚点。

包含：

- 保存商品按钮
- 取消/返回按钮
- 当前说明文案
- 保存中状态反馈

目标：

- 用户在任意编辑深度都能快速执行保存
- 取代“必须滚到底部才能保存”的低效模式

### 9.2 区块二：发布设置

包含：

- 分类
- 可见等级

目标：

- 将影响商品曝光和展示范围的设置集中管理

### 9.3 区块三：商品属性

包含：

- 是否共享
- 是否热门

目标：

- 将开关型属性集中到右栏处理
- 让左侧内容流更纯粹

### 9.4 区块四：积分与变体

包含：

- 积分抵扣开关
- 积分抵扣比例
- 变体组 ID
- 变体标签

目标：

- 统一处理偏运营和商品组织结构的配置
- 避免这些“配置型字段”打断左侧内容编辑

## 10. 视觉设计

### 10.1 卡片层级

左栏使用较强的内容卡片层级：

- 独立区块卡片
- 更明确的区块标题
- 更大的输入空间

右栏使用较紧凑的配置卡片层级：

- 小卡片垂直堆叠
- 操作卡最突出
- 其余配置卡保持低干扰

### 10.2 主次关系

视觉主次要非常明确：

- 左边是编辑主体
- 右边是设置辅助

因此不应让右栏在视觉上压过左栏，只让保存卡成为明确操作焦点即可。

### 10.3 保存反馈

保留现有表单保存遮罩和保存中状态，不改变保存交互语义，只迁移到新布局下继续工作。

## 11. 组件拆分设计

### 11.1 总控组件保留

保留：

- `_workers_next/src/components/admin/product-form.tsx`

职责：

- 维护现有本地状态
- 处理提交
- 汇总 `FormData`
- 串联各子区块组件

### 11.2 拆分子组件

本次按以下子组件拆分：

- `product-content-section`
  - 负责名称、Slug、描述、价格、限购、购买须知
- `product-media-section`
  - 负责主图、上传、图库、预览
- `product-questions-section`
  - 负责购买提问列表编辑
- `product-settings-sidebar`
  - 负责分类、可见性、共享、热门、积分抵扣、变体、保存操作

这样做的价值在于：

- 让 `product-form.tsx` 从“超大渲染文件”变成“表单协调器”
- 后续再调整某个区块时，不需要反复在一个超长 JSX 文件里穿梭

## 12. 实现边界

### 12.1 计划改动文件

- `_workers_next/src/app/admin/layout.tsx`
- `_workers_next/src/components/admin/sidebar.tsx`
- `_workers_next/src/components/admin/product-form.tsx`
- 若干新的商品编辑区块组件文件

### 12.2 明确不改

- 不修改 `saveProduct()` 入库逻辑
- 不修改商品字段提交结构
- 不修改移动端菜单交互模式
- 不扩散成后台全页面视觉重做

## 13. 风险与约束

### 13.1 布局风险

固定侧边栏后，必须处理好：

- 桌面端高度
- 右侧内容区滚动
- 页面宽度收缩
- 小屏断点下的自动折叠

否则容易出现内容被遮挡或滚动冲突。

### 13.2 表单状态风险

`product-form.tsx` 当前已经承载多类本地状态：

- 图片上传状态
- 图库状态
- 购买提问状态
- 积分抵扣状态
- 保存状态

拆分组件时必须保持：

- 字段名不变
- `FormData` 不变
- 本地 state 驱动关系不变

### 13.3 功能回归风险

以下行为必须保持一致：

- 新建商品
- 编辑商品
- 图片上传与预览
- 图库增删和设封面
- 购买提问增删改
- 积分抵扣配置保存
- 保存成功后跳转列表页

## 14. 验证方案

### 14.1 桌面端后台骨架验证

- 打开后台任意长页面
- 向下滚动时左侧菜单固定不动
- 右侧主内容区可正常独立滚动

### 14.2 商品编辑页布局验证

- 桌面端显示左内容右配置双栏
- 右栏操作卡保持吸顶
- 保存按钮始终易于触达

### 14.3 移动端验证

- 后台继续使用抽屉菜单
- 商品编辑页自动折叠为单列
- 没有横向溢出和交互错位

### 14.4 功能回归验证

- 新建商品流程正常
- 编辑商品流程正常
- 保存成功和失败提示正常
- 现有 loading 遮罩继续工作

## 15. 结论

本次推荐方案是：

- 后台桌面端固定左侧侧边栏
- 商品编辑页采用“左内容、右配置”的双栏布局
- 保持业务逻辑不动，仅重组信息架构和组件结构

这是当前最稳妥、最符合后台长表单编辑场景的方案，也能为后续继续扩展商品配置提供更稳定的承载结构。
