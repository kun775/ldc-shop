# 积分订单退款与删除

- 新建积分兑换及其他零元订单使用本地生成的纯数字交易号。正式 `ORD` + UUID 订单号完整编码为 43 位数字（四位保留前缀 + 39 位十进制 UUID），不截断身份，避免不同订单共用交易号；旧非 UUID 订单号按完整 UTF-8 字节编码。零元订单不产生支付平台交易号，也不向网关发送该编号。
- 历史固定号和 `POINTS_REDEMPTION:<订单号>` / `ZERO_PRICE:<订单号>` 统一按数字号展示、复制和搜索；历史数据库不批量改写。真实支付交易号保持原样。
- 已支付或已交付、实付为零且使用积分的订单可以点击「退款」。确认后返还积分并进入现有卡密作废流程，不调用支付网关，也不要求商户支付凭据。
- 现金加积分订单仍通过支付网关退款，并按原流程返还积分。已退款订单重放不重复退款，删除已退款订单也不会再次返积分。
- 单条删除被卡密中心账本或履约状态拦截时明确报告原因；批量删除显示实际删除和保留数量，并保留未删除订单的勾选。
- 卡密中心已确认作废且无待处理操作时，历史订单可以删除；卡密中心原始映射记录仍保留。尚未作废或仍有待办时继续拦截删除。

失败 `not_found` 批次可先在卡密中心页面「手动丢弃」：未交付订单的失效预留引用一起清理，其他有效卡引用保留。确认已付款且履约锁过期（十分钟）、没有交付或使用记录时，会原子回收旧锁并恢复为已支付。随后可删除该失败订单，或补充有效库存再重试履约。有效锁、已交付、已售出和已使用记录仍受保护，失败提示显示具体阻塞原因。

Sell 每轮只发起一次请求，临时错误至少退避一分钟，并采用指数退避；累计失败最多 12 次，`not_found` 首次即停止。执行核心和人工入口都不能重试已放弃的待办。订单处于 `processing` 时前后台展示「已支付·履约中」，已核验付款的订单发生交付异常仍回落为 `paid`。

本次没有新增数据库结构或执行线上退款、丢弃、删除操作；新增行为需部署后生效。
